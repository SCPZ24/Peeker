# Peeker 推广前产品化更新需求

**交付对象：** Coding Agent  
**文档日期：** 2026-09-12  
**仓库：** `https://github.com/SCPZ24/Peeker`  
**输入依据：** 用户已确认本轮视觉、交互和性能优化方案，并追加中文／日文／英文多语言配置。  
**定位参考：** 上一轮代码审阅参考 `main@bed3a19`。本文不是对最新 HEAD 的再次验收；实施时必须读取当前代码，不得为了匹配参考版本回退用户已有改动。

> 本轮不是新增一批功能，也不是重写架构，而是把现有五张功能卡与公共提示系统收口成一个完整、克制、可靠的 macOS 产品。
>
> 产品原则：**平时安静，交互准确，关键时刻有表现力；完成之后，重新安静下来。**

## 1. 执行目标与不可变边界

请直接依据本文完成实现、测试和必要的文档更新，而不是只输出建议。首先阅读仓库的项目指令、构建流程、现有测试和本轮相关代码，记录当前 HEAD 与工作区状态，再按模块推进。设计方向已确认，不需要重新发起视觉方案选择；只有真实阻塞实现、且无法从代码确定的问题才需要明确报告。

本轮必须同时覆盖 Scheduler、Agentor、Pusher、Timer、Targetor、公共消息提示、性能优化和文末多语言配置。以下约束适用于每一个模块：

| 编号 | 强制要求 |
| --- | --- |
| G-01 | 保持原生 macOS 技术路线，沿用现有 SwiftUI 与必要的 AppKit 桥接。不得引入 WebView、Electron、网页 UI 或第三方 UI／动画／本地化框架。 |
| G-02 | 保持**单一常驻 App 进程**。已有 CLI、Agentor hook 等短生命周期入口不属于新增常驻服务；保留其用途，不新增 daemon、sidecar、独立渲染器、Python／Node 常驻辅助进程。 |
| G-03 | 保留现有模块边界、CLI／IPC 协议、持久化模型和业务数据。不得为美化界面顺便迁移数据库、重写拖动桥接、重构 Agent 集成协议或新增跨模块事件总线。 |
| G-04 | 公共能力优先复用 `FunctionCardKit`、`PromptCenter`、现有协调器和各模块 Store。必要的视觉 token、生命周期状态和少量事件元数据可以添加，但不建设一套通用 UI 引擎。 |
| G-05 | 视觉反馈不能改变业务事实。成功庆祝以业务操作真正成功为前提；失败必须可见，不能吞掉错误后显示成功或关闭编辑器。 |
| G-06 | 保留已有任务、计时、周期、重复日程、打卡分档、问答提交、权限和 writeback 规则。界面语言切换也不得改变这些规则。 |
| G-07 | 不覆盖用户未提交的工作，不擅自切换／重置分支；不自动发布版本、打 tag、推送远端或调整发行渠道。遵循仓库现有工作约定。 |
| G-08 | 验收包括运行中的应用、交互流程与资源开销，不以“代码能编译”代替产品验收。无法执行的测试必须单独标注，不能声称已通过。 |

本文出现的尺寸、字号和动画时长是**明确的设计起点**，可以依据实际排版与实机观感小幅调整；交互语义、信息可读性、状态正确性、单进程与停刷要求不是可选项。不要通过压小字体、隐藏重要内容或增加常驻资源来解决布局问题。

## 2. 统一视觉与交互规范

### 2.1 黑色灵动岛与原生控件各司其职

保留 Peeker 黑色灵动岛主体及与屏幕顶部的关联，不把“原生化”理解为所有内容都铺 Liquid Glass。岛内使用稳定的黑底和少量低对比深色内容表面；编辑器、菜单、设置、popover 等使用系统控件与合适的原生外观。

不要在一张内容卡里同时叠加明显灰底、毛玻璃、白色后板、强描边和持续发光。只保留表达当前状态所需的视觉层次。不要因为添加材质而改变现有窗口层级、焦点行为或引入新的独立窗口系统。

黑色岛内应有正确的深色语义上下文，正文与辅助文字优先使用 `.primary`、`.secondary` 等语义层级。不能让岛内的固定深色外观或白字设置意外污染原生编辑器；也不能继续通过强制浅色、强制黑字的补丁解决控件可读性。分别检查浅色／深色系统外观下的控件与弹出层。

### 2.2 字体、颜色、布局

使用系统字体，数字进度与时间读数按需要使用等宽数字。正文以 13–14 pt、辅助信息以 11–12 pt 为起点；不再用 7–8 pt 小字承载星期、月份、说明等关键内容。字号可按用途调整，但不得用过小文本换取表面上的紧凑。

颜色有稳定的语义：中性文字承载内容，任务分类色承载分类，小面积成功色承载成功，琥珀色承载注意，红色承载失败。不要将整段正文染成高饱和状态色，也不要只靠颜色表达状态。

统一相近组件的间距、圆角、hover 和按压反馈。公共 token 只抽取确实重复的参数，留在现有模块中，不为本轮新建独立设计系统 package。

所有展开布局遵守实际屏幕可用空间和刘海安全区域。空间不足时使用合理的自适应列数、局部滚动或已有尺寸适配能力，不把内容推到屏幕外，也不缩小关键字号。

### 2.3 命中、焦点与无障碍

按钮和事件块的可点击区域必须匹配可见区域，不能只有文字可点。装饰性 overlay 不拦截点击；相邻空白区手势不能穿透已有控件。重要操作必须有可发现的按钮、菜单或键盘等价路径，不能只能依赖精确 hover 或拖动。

保留已有焦点、拖动、popover 和编辑保持机制。用户输入期间不自动收起，不因新消息切换卡片，不因重绘丢失焦点。提交快捷键不能抢占多行输入的正常换行行为。

响应系统“减少动态效果”，将飞行、缩放、扫光和持续循环替换为静态状态或短淡入淡出；检查“减少透明度”、增强对比度和辅助功能标签。重要状态必须有文字或形状表达，不能仅靠动画、亮度或颜色。

## 3. 公共消息提示：接通语义，统一反馈去向

### 3.1 改造范围

优先完善已有 `FunctionCardPrompt`、`FunctionCardPromptStyle`、`FunctionCardPromptGlyph`、`PromptCenter` 和 `IslandRootView`，不新建四套 toast。检查各功能模块的发布入口，确保业务事件显式使用正确的提示语义，而不是全部落入默认 `.standard`。

| 编号 | 要求 |
| --- | --- |
| N-01 | Pusher、Timer、Scheduler、Targetor 共用一种提示结构、字体层级、入场／退场语言和交互规则。 |
| N-02 | 普通确认、成功、注意和失败具有可辨认的表现；颜色集中在图标及少量强调区域，正文保持可读的中性色。 |
| N-03 | 入场动画按实际开始展示的时间计算，不按业务事件的发生时间直接计算。 |
| N-04 | 同一次成功事件只选择一个主要反馈位置，避免原位庆祝后排队再庆祝一次。 |
| N-05 | 提示不抢焦点，不打断拖动、编辑和 Agent 回答，不自动切换正在使用的卡片。 |
| N-06 | 保留现有排队、token、撤销、容量、来源禁用清理与失效处理；不把视觉更新扩展成全新消息调度架构。 |

### 3.2 消息语义与表现

| 事件类别 | 表现要求 | 典型事件 |
| --- | --- | --- |
| 普通操作确认 | 中性图标与短过渡，不使用成功庆祝等级的动效 | 新建、编辑、删除、未完成状态之间的普通移动 |
| 成功完成 | 小面积成功色、一次明确的图标动作，随后回到静态 | Timer 自然结束、Pusher 进入 Done、Targetor 打卡成功 |
| 需要注意 | 琥珀色语义图标、明确文案和一次克制的注意反馈，不无限闪动 | Scheduler 日程临近、需要用户处理的提示 |
| 失败 | 红色语义图标、原因与必要的操作入口，不表现为成功 | 保存失败、移动失败、打卡失败 |
| 活动状态 | 仅在确有持续活动需要表达时使用，活动结束或不可见时停止 | 已有需要持续活动指示的事件 |

普通确认不必每次都占用岛级消息。文案应直接表达用户理解的结果，不把 enum 的 raw value、内部状态名或技术错误代码直接作为主要提示。

单次入场、成功或注意动效完成后必须停止动态更新，不能因为提示还在停留而继续 30 fps 驱动一个已静止图标。默认不增加全局音效、全屏粒子或持续闪光。

### 3.3 事件时间与展示时间分离

保留 `occurredAt` 的事件发生语义；在提示真正开始展示时记录展示起点，入场动画使用该起点。排队数秒后出现的成功消息，也必须完整播放一次入场，而不是直接落到动画终态。

提示 identity 与 token 保持稳定。因普通重绘不重播；同一消息从排队变为展示时才启动本次入场。取消、撤销、来源禁用和提示离开视图时，关联任务都应正确清理。

只添加完成这些目标所需的少量展示状态，不持久化动画进度，也不引入永久增长的去重记录。

### 3.4 反馈去向与防重复

用户正在当前卡片中执行操作时，优先用原位确认。例如卡片进入 Done 并已经完成反馈，收起灵动岛后不再播放同一事件的成功庆祝。

异步事件、当前不可见的模块事件，以及 CLI 发起而用户未在界面中看到的变更，可以使用岛级提示。若需要区分事件来源与是否已经原位呈现，可增加最小必要的元数据，但不可仅依据“来源模块当前被选中”粗暴丢弃事件：当前模块也可能收到用户未看见的异步变化。

岛已展开时，在页面固定且不遮挡输入的位置呈现必要提示；不要替换正在使用的内容，不自动切卡，不在随后收起时补播已呈现的同一条庆祝。失败不能因防重复逻辑被静默吞掉。

### 3.5 消息态的点击行为

提示整条可点击，明确点击才进入来源功能；消息态的 hover 只提供悬停反馈或必要的展示保持，不直接打开整个功能页面。**尤其 Scheduler 提醒不得因为鼠标掠过而自动展开周历。**

这条规则只针对消息态，不借机删除普通收敛态已有的 hover 展开能力或相关用户设置。进入来源卡片时继续遵守现有 popover、拖动和编辑保持机制。

长文案使用可理解的摘要、合理截断和详情入口，不通过无限横向扩展或缩小字号展示。消息正文还应遵守文末的语言配置。

## 4. Scheduler：可靠、紧凑、可交互的周历

### 4.1 布局重排

保留周历产品形态，不新增日／月视图等额外产品范围。布局从上到下为：导航工具行、独立星期／日期标题、内容驱动的全天区域、占据剩余高度的时间网格。

| 编号 | 要求 |
| --- | --- |
| S-01 | 星期／日期标题独立固定，不再混入全天日程列，也不随全天事件数量改变基础标题高度。 |
| S-02 | 全天区域按内容收缩，不使用能吞掉剩余垂直空间的 `Spacer` 或不受控高度。无全天事件时不留下大块空白。 |
| S-03 | 全天事件默认最多两行；单行以 20–22 pt、两行总高约 48–52 pt 为起点。更多事件通过 `+N` 入口访问，不再直接截断后无入口。 |
| S-04 | 时间区域占据剩余有效高度并可滚动，保留合理的初始滚动位置。今天只使用克制强调，网格线退后，不给整列铺高亮色。 |
| S-05 | 定时事件改为低饱和填充、细分类色侧边及清晰文字。重叠事件必须能并列访问，不能互相完全覆盖。 |
| S-06 | 保留上一周／今天／下一周，并提供明确的新建入口。布局随屏幕可用尺寸适配。 |

全天区展开更多内容时使用轻量列表或 popover，不让主周历被无限增高。跨日的全天事件和定时事件仍然显示为各自正确的业务 occurrence，不因布局拆分改变事件身份。

重叠布局需覆盖两个事件、三个以上事件、包含关系和首尾恰好相接的事件；狭窄事件也必须可访问。短事件的最小可见高度要与命中区域一致，不能无意覆盖相邻事件的全部点击区域。

### 4.2 点击、创建与详情

事件块应使用真正的交互控件，将尺寸、padding、背景和命中形状统一到 label 内。点击标题、边缘、背景空白都打开同一个事件，而不是只有字形区域触发。

全天事件也必须是独立可点击控件。点击已有事件不得触发新建；`+N` 与全天空白的操作不能相互穿透。默认采用事件单击查看／编辑，时间空白双击新建，并保留明确的新建按钮；全天区域同样区分已有事件与新建意图。

详情使用与事件相关联的原生 popover，处理好滚动、切周、事件删除后的锚点与关闭状态。不能继续依靠强制浅色、强制黑字修正外观。

### 4.3 保存、删除与重复事件正确性

保存／删除仅在确认成功后关闭编辑器。失败时保留全部输入并显示错误，允许用户修正或重试；禁止用 `try?` 吞掉错误后无条件清空 draft。

点击重复事件时保存所点 occurrence 的稳定身份与原始 occurrence key。编辑／删除前明确操作范围，使用后端已有的范围能力；不默认把针对一次 occurrence 的操作施加到整个系列，也不为本轮扩展新的重复规则引擎。导入事件和原有编辑限制保持不变。

日期布局与周切换使用日历语义，不把一天固定等同于 86,400 秒来推导所有本地日期。检查跨月、跨年、跨日与夏令时边界，不改变用户时区和既有业务日规则。

当前时间线只在需要时按分钟级更新。周历不可见、或显示的周不包含当前时间时，不持续为时间线刷新。

## 5. Agentor：统一呼吸与可读的问题表单

### 5.1 一组 Agent 使用同一个节拍

目标不是把多个动画的 duration 碰巧设成同一个数，而是统一**时间基准、周期、相位、可见性与生命周期**。

| 编号 | 要求 |
| --- | --- |
| A-01 | 所有在飞 Agent 的活动表现共享一个呼吸相位，以舒缓的 3.2 秒周期为起点。 |
| A-02 | 收敛态的图标组与展开态的会话强调使用同一个节拍；不能分别按视图出现时间重新计时。 |
| A-03 | 新增 Agent 加入当前相位；Agent 退出不重置其余会话；收敛／展开和视图重建不重置节拍。 |
| A-04 | 不再按 session 的 `startedAt`、`generation` 或列表 index 注入不同相位。会话执行计时仍保留自己的业务时间。 |
| A-05 | 等待回答通过语义图标、少量强调色和文字体现，不新增一套更快的独立呼吸节律。 |
| A-06 | 可见 Agent 变多时，整体动效强度不能按卡片数量无界叠加。不再每张卡独立扫光、叠大光晕。 |
| A-07 | 没有活跃 Agent、相关视觉不可见或启用减少动态效果时停止呼吸驱动。业务监测不因视觉停止而停用。 |

共享呼吸只属于小范围视觉上下文，不是业务服务。使用稳定、适合动画的共同时间基准，避免系统时间调整造成逐卡跳变。唤醒后共同恢复到一致相位，不逐卡补播历史帧。

不得通过每帧修改全局业务 Store 来驱动整个应用刷新，也不得为每个 Agent 分别创建常驻计时循环。共享逻辑留在现有模块内；纯相位计算应能用可控时间进行单元测试。

单 Agent、多 Agent 与等待状态的持续视觉语言应一致，避免把旋转环、跳动点、边框扫光和呼吸全部叠在一起。状态变化可以有一次局部反馈，但不能每次都闪一圈成功绿，也不能打断共同节拍。

### 5.2 问题面板重排

使用清晰的信息结构：**会话头 → 待回答请求 → 编号问题 → 纵向选项／输入 → 操作区**。

会话头保留 Agent 标识、会话名称、运行时长与状态。一个会话下多个请求按稳定身份分组；一个请求下多个问题完整展示并编号，不能为缩短界面而丢弃问题或把多个问题误合并。

问题正文以 13–14 pt 为起点，标题适度加粗，说明以 11–12 pt 为起点。主要内容与辅助信息使用明确的语义层级，不再通过多层灰色背景与各种白色透明度制造区分。

单选使用纵向单选项，多选使用纵向复选项。整行选项可点，长标题与说明可以换行；移除标签云式 `FlowLayout` 作为长问答的默认排版。需要自定义答案时提供清晰的入口，避免难以理解的孤立 `Other` 标签。

问题间用留白或轻分隔线，不各自再套一张亮灰色卡片。长表单合理滚动，提交与回退入口保持容易找到；不要出现用户必须在多个嵌套小滚动区里寻找按钮的情况。

### 5.3 保留问答协议与输入状态

保留即时单选提交、多问题提交、自定义答案提交、`supportsWriteback`、schema 安全检查、正在提交状态与“在 Agent 中回答”的回退路径。不为统一按钮样式改变提交协议。

草稿、焦点与选中状态绑定稳定的 request／question ID。新增其他 Agent、状态刷新、视图收敛再展开、语言切换，均不得清空现有回答。错误或过期请求应有明确状态，不静默丢掉用户输入。

多个问题同时出现时检查中文／日文输入法组合输入、多行文本、Tab 导航和选项键盘操作。操作期间不自动切换会话、抢焦点或收起灵动岛。

## 6. Pusher：完成时有回报，完成后安静下来

### 6.1 Done 的稳定视觉状态

任务进入 `.done` 后使用中性深灰卡面，原来的紧急度圆点变为克制的完成符号，标题仍然清晰可读。不要保留一张看起来仍在催办的高饱和彩色任务卡。

灰色表示“完成”，不表示控件禁用。编辑、拖动、菜单与键盘路径仍然有效。任务拖回 Planned 或 Processing 后恢复原来的紧急度颜色；不要修改数据里的 urgency 来实现去色。

### 6.2 完成反馈时序

建议反馈链：**落位 → 轻微吸附／回弹 → 完成符号出现 → 彩色背景退成中性灰**，以 350–500 ms 为起点。局部高亮可以使用一次，不给整个 Done 列刷大面积绿色，不增加全屏庆祝。

| 编号 | 要求 |
| --- | --- |
| P-01 | 沿用既有拖动事务与回滚路径。可立即反馈落点／位置，但成功符号和庆祝必须等持久化确认。 |
| P-02 | 只对从非 Done 状态真正进入 Done 的成功转换庆祝；Done 内排序、无变化拖放和数据载入不庆祝。 |
| P-03 | 持久化失败时回滚、展示失败，不能先庆祝后无声恢复。 |
| P-04 | 同一事务仅庆祝一次；视图重建、重新展开或重复回调不重播。 |
| P-05 | 当前页面已原位反馈时，不再在收起后补播相同岛级成功消息。 |

动效触发应绑定成功事件／稳定 token，而不是靠卡片 `onAppear` 或初次看到 `.done` 状态推断。启用减少动态效果时直接切换完成样式，保留明确的结果确认。

## 7. Timer：自然结束，消除双重亮绿

日常任务与临时任务使用同一套完成样式，不各自保留不同的绿色补丁。

完成时进度条平滑走满，随后降低饱和度或强调程度；“已完成”使用辅助文字色，右侧使用与播放／暂停控件位置和尺寸一致的简单线性勾。移除突兀的绿色实心圆与同时变绿的文案组合。结束后保留清晰的任务名和有用信息，例如“已完成 · 25 分钟”。

完成后的稳态要安静，但不能把整行透明度降到难以阅读；进度条与控件槽位保持稳定，不因完成状态切换而跳动布局。完成状态不能被设计成禁用态。

| 编号 | 要求 |
| --- | --- |
| T-01 | 任务行负责表达“已完成”，公共提示负责表达“刚刚结束、值得注意”，避免双重高强度强调。 |
| T-02 | 保留计时、暂停、恢复、临时任务、自然完成与刷新规则，不用动画时间代替业务计时。 |
| T-03 | 重新展开、重载已完成任务或切换语言不重播完成动画。 |
| T-04 | 已完成和未运行的任务行不继续为倒计时每秒刷新；只更新确实需要变化的可见读数／统计。 |
| T-05 | 停止视觉刷新不影响后台计时准确性、自然完成触发和睡眠唤醒后的状态恢复。 |

## 8. Targetor：进度描边、开放日历与三档庆祝

### 8.1 卡片视觉职责分离

保留通过描边亮度表示打卡进度的既有逻辑和分档，保留 `本周期 N/M` 与必要的进度信息。亮度不是唯一进度表达。

去掉白色后板翻出、偏移旋转和明显缩放叠在一起的 hover 表现，改成稳定的深色卡面。**进度描边只表示进度，hover 不改变这条描边的进度含义。**

hover 只做轻微卡面提亮和操作提示，至多极小位移。卡片的布局、轮廓和相邻关系保持稳定，不能通过亮度变化让未开始目标看起来已完成。

### 8.2 日历直接显示在黑底上

移除右侧永久存在的背景框、带色框与描边。日历直接组织在黑色岛内，使用月份／年份、目标标题、星期、日期与留白建立层级，而不是再套一个装饰盒子。

右侧宽度以 270–300 pt 为起点，利用有效高度，不再强制塞进 190×190 的小正方形。左侧按空间调整列数或使用已有滚动能力，不能为了扩大右侧把目标标题缩成小字。

| 编号 | 要求 |
| --- | --- |
| H-01 | 默认保留“最近九周”总览，不擅自替换统计口径。热力格以 18–22 pt 为起点，标签清晰。 |
| H-02 | 目标日历保留已有月／年粒度。月历日期区以 28–32 pt 格子为起点，星期、月份和年份不再使用微小字号。 |
| H-03 | 年度视图、周频目标的配色与已有统计语义保持一致，不能因放大布局改变周期归属。 |
| H-04 | 日期格可通过 hover／辅助功能获得日期与相应记录信息；进度／次数不能只靠格子色深理解。 |
| H-05 | 调整尺寸后拖动落点几何同步更新，不因取消边框导致实际命中区域错位。 |

### 8.3 预览、选择与拖动打卡

hover 可预览目标日历，点击或键盘选择可固定当前目标；不要在指针刚离开目标卡、准备移向右侧日历时立刻清空正在查看的内容。保留清晰的返回总览路径。

日历读取按目标与数据版本管理，避免鼠标移动就重复读取相同数据。快速切换目标时旧异步结果不得覆盖新选择；必要时取消过时任务或检查请求身份。打卡成功后刷新对应日历与总览，不做无关全量重载。

拖动期间，右侧临时显示明确落点、当前目标及“松开以打卡”。取消拖动后回到原来的日历／选择；不要借拖动提示恢复永久的大色框。继续沿用现有打卡锁定、展开保持和防重复机制。

### 8.4 重做三种成功庆祝

保留现有 `.started / .progressing / .completed` 的判定与阈值，只改变视觉。不要为动画重新定义打卡阶段；`.notStarted` 不凭空触发成功庆祝。

| 阶段 | 表现 | 设计时长 |
| --- | --- | --- |
| 起步 | 上升符号轻轻上提，计数更新，目标描边点亮到新进度 | 350–450 ms |
| 推进 | 火箭／推进符号短距离上行，配极少量短尾迹，随后稳定；进度与记录同步可见 | 550–700 ms |
| 完成 | 完成徽章显现、勾画出，少量局部放射线收尾，描边停在完成亮度 | 800–1000 ms |

动作落在图标、计数、进度和当天记录上。移除整个右侧区域闪白、粗白边闪烁和两条生硬白色矩形横扫的旧表现；不要遮住日历，也不扩展为全屏粒子特效。

成功庆祝在打卡事务真正成功后触发，跟随稳定 token。失败、过期拖动、重复结果、重绘、重新展开和数据重载不触发。打卡达到上限时继续执行现有业务限制。

减少动态效果时使用静态完成状态或短淡入淡出，取消飞行、缩放、扫光和粒子。动画结束后立即停止相关时间线并释放临时状态；动画不能靠长期锁住页面维持。减少动态效果下也必须及时释放展开保持和操作锁。

## 9. 性能与资源生命周期

轻量化是发布验收条件，不是视觉完成之后的附带优化。应区分**业务仍在运行**和**对应视觉正在屏幕上可见**：后台计时、Agent 事件接收、日程提醒继续工作，不代表隐藏视图也应每帧刷新。

| 编号 | 要求 |
| --- | --- |
| F-01 | 不以 `opacity(0)`、被裁剪或不可点击等同于已停止。检查 `IslandRootView` 中同时挂载的展开／收敛内容，明确驱动其可见性。 |
| F-02 | 隐藏、切走、退出和无活动状态下的纯装饰时间线暂停或移除；持续视觉动画数量不能随历史视图或会话累积。 |
| F-03 | Agentor 只使用共享的小范围视觉驱动，避免每帧 invalidation 波及整个 Store、列表和其他卡片。慢速呼吸以 30 fps 或更低为起点，不强求 60 fps。 |
| F-04 | 单次庆祝和提示入场有明确结束时间，结束后不再持续刷新静止画面。使用系统动画能力，不以轮询实现本可一次性完成的过渡。 |
| F-05 | 已完成／未运行 Timer 行停止无意义秒级更新；Scheduler 当前时间线只在需要时按分钟级更新。 |
| F-06 | 不在动画帧里访问数据库、扫描文件、解析 Agent 数据、构建整周／整年日历或执行网络请求。 |
| F-07 | 避免多层大面积 blur、无界 glow、重复离屏合成和为每个小组件创建独立刷新循环。装饰强度和资源使用均需有上界。 |
| F-08 | 异步任务、观察者、计时源和临时动画状态在关闭、禁用、撤销、重建或不再需要时正确取消／释放。 |
| F-09 | 停刷不得以牺牲计时、提醒、输入草稿、持久化结果和 Agent 通信为代价。睡眠／唤醒和屏幕变化后状态正确恢复。 |

### 9.1 测量方式

在同一台 Mac、相同构建模式、相同数据与相同观察时长下，记录修改前后 CPU、内存、活跃视觉刷新源及必要的渲染表现。无绝对 CPU／内存承诺；需要提交真实对比，而不是只写“已优化”。

至少测量：空闲收敛；Agentor 1／2／5／10 个会话；展开其他卡片而 Agentor 在后台；Timer 运行与全部完成；Scheduler 可见／不可见；庆祝进行中与结束后；连续展开收起；减少动态效果开启。

空闲且无可见动态内容时，不得仍有本轮新增的持续动画 tick。庆祝结束后资源回到相应稳态；反复打开关闭不能造成常驻任务或内存持续增长。可使用现有工具或临时调试记录验证，不引入生产环境常驻性能监控服务。

## 多语言配置

允许用户选择多个语言。在设置-通用-语言中，可以选择语言。

当前先适配中文/日文/英文。

### 配置行为

本轮将“可选择多个语言”实现为**提供多个可切换的界面语言选项**：应用当前使用用户选定的一种语言，不同时混排三套文案，也不新增多语言优先级编辑器。

入口固定为**设置 → 通用 → 语言**，使用原生选择控件。提供 `跟随系统`、`中文（简体）`、`日本語`、`English`。未显式选择时默认跟随系统；匹配到本轮支持的中文、日文或英文时使用对应资源，未支持的系统语言回退到英文。本轮中文资源先实现简体中文，不额外扩展繁体资源范围。

语言偏好在重启后保留。手动选择优先于系统语言；选择“跟随系统”时恢复自动匹配。语言名称使用各语言的自称，确保用户选错语言后仍能找到正确选项。

### 生效范围与文案要求

本轮必须覆盖五张功能卡、公共消息提示、设置、popover／编辑器、菜单、空状态、错误、按钮、提示帮助文本与辅助功能标签。不能只翻译设置页面或主标题。

固定 UI 文案使用完整的本地化模板，包含参数、数量与单位，避免通过拼接中文片段生成英文／日文。新增文案与本轮涉及的既有可见硬编码文案均纳入同一资源体系。

| 中文参考 | 日文参考 | 英文参考 |
| --- | --- | --- |
| 跟随系统 | システム設定に従う | Follow System |
| 语言 | 言語 | Language |
| 今天 | 今日 | Today |
| 全天 | 終日 | All-day |
| 已完成 | 完了 | Completed |
| 等待回答 | 回答待ち | Awaiting response |
| 提交回答 | 回答を送信 | Submit answers |
| 打卡成功 | 記録しました | Check-in recorded |
| 松开以打卡 | ドロップして記録 | Drop to check in |
| 保存失败 | 保存できませんでした | Couldn't save |

上表用于统一术语与语气，不代表全部资源。根据具体语境调整单复数、敬体与单位，使英文／日文自然可读；错误提示应给出可操作的信息。

`Peeker`、功能模块品牌名和 Agent 产品名可以保留原名。用户输入的任务名、目标名、事件标题／备注以及 Agent 发来的问题、选项和自由文本**不得自动翻译、改写或覆盖**。

`Planned / Processing / Done` 等用户可见状态标签可本地化，但内部 enum raw value、数据库字段、稳定 ID、命令名、CLI 参数、IPC schema 与机器可读返回字段必须保持兼容。不能通过改内部标识符实现翻译。

### 本地化实现边界

优先使用 Apple 原生本地化资源和格式化能力，结合当前 SwiftPM／App 打包方式接入，确认资源确实进入可运行的 `.app`。不得只添加未被构建系统处理的资源文件，然后宣称已支持多语言。

需要的偏好存储、语言解析与资源读取逻辑保持轻量，并放在现有合适边界内，不引入大型 i18n 框架、远程翻译服务、额外数据库或后台进程。若系统默认本地化方式不足以完成应用内即时切换，可使用最小必要的共享语言上下文，不建设通用翻译平台。

日期、星期、月份、数量和时间单位按当前语言合理格式化，但不得因此修改用户时区、计时值、周期边界、业务日刷新时刻、周起始业务规则、日程重复规则或历史打卡归属。展示语言与业务时间计算明确分离。

消息尽量在展示时按当前界面语言生成。必要时保留少量语义模板与参数，让排队消息遵守当前语言；不要对已经生成的用户内容做字符串替换式“翻译”，也不要为此重写事件系统。

### 即时切换与状态保持

切换语言应即时更新现有应用界面，不要求退出应用，不启动新进程。不得通过销毁整个 App 根状态的方式换语言。

正在运行的 Timer、Pusher 拖动事务、Targetor 打卡事务、Agentor 会话／待回答请求、编辑器未保存的输入和当前日历选择均保持不变。语言更新不得重播成功庆祝、重启呼吸周期、重复发送请求或抢走输入焦点。正在排队的消息按新语言展示，已展示消息更新文案时不重新计作一次事件。

英文较长文案、日文排版和三语日期标题均需重新检查布局。通过合理换行、列宽与空间分配解决，不把字体缩回微小字号，也不让提交按钮、星期标题或消息摘要不可读。

### 多语言验收

| 编号 | 必须通过的验收 |
| --- | --- |
| L-01 | 设置 → 通用 → 语言入口存在，四个选项可选，保存后重启仍按偏好生效。 |
| L-02 | 首次运行及“跟随系统”的中／日／英匹配正确；不支持的语言有明确且可测试的英文 fallback。 |
| L-03 | 五张卡、公共消息、设置、编辑器、菜单和辅助功能文本均有对应资源；除品牌与用户内容外，不混入遗漏的硬编码语言。 |
| L-04 | 中／日／英资源键完整对应，缺失资源可以在测试或调试阶段发现；用户界面不显示裸 key。 |
| L-05 | 切换语言不丢输入草稿、不停止计时、不重复打卡／提交、不改变数据库与 CLI／IPC 语义。 |
| L-06 | 日期和单位显示合理，业务时区、周期、刷新时刻和历史数据不变。 |
| L-07 | 三种语言分别走通 Scheduler 编辑、Agentor 多问题回答、Pusher 完成、Timer 结束、Targetor 打卡和公共消息流程；长文案没有遮挡、截断关键操作或异常布局。 |
